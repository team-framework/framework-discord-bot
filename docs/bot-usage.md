# Framework 문서 봇 사용법

## 논의 중 문서 확인하기

채널이나 공개 스레드에서 ChatGPT Agent를 멘션하거나, Agent의 메시지에 답글을 달면 대화에 참여한다. 기존 위키의 근거를 찾아 질문에 답하고 수정할 내용을 제안한다. 추론 강도는 `/reasoning`의 effort에서 선택한다. 기본값은 `low`다.

위키 원문은 웹 문서 화면에서 읽는다. 웹 챗봇은 팀 GitHub 계정으로 로그인한 뒤 사용한다. 답변의 출처 링크에서 실제 문서를 확인한다.

## 다른 팀원에게 논의 전달하기

스레드 안에서 `/스레드-정리`를 실행한다. 봇이 최근 대화를 시간순으로 정리해 원래 채널에 남긴다. 이 명령은 팀원의 정보 공유를 위한 요약이다.

## 위키에 반영할 결론 제안하기

대상 일반 채널이나 공개 스레드에서 `/위키-제안`을 실행한다. 기본 범위는 최근 100개 메시지다. `개수`로 범위를 줄이거나, `시작`·`끝`에 메시지 ID를 넣어 특정 논의를 선택할 수 있다. 메시지 ID는 Discord 개발자 모드를 켠 뒤 메시지 메뉴의 ID 복사에서 얻는다.

봇은 같은 채널·스레드에 최종 결론과 변경안 파일을 올린다. 파일에는 읽은 범위, 미검증 항목, 정확한 변경 diff와 적용 후 문서가 담겨 있다. 첨부파일의 본문은 자동으로 읽지 않는다. 결론에 이미지·파일 내용이 필요하면 사람이 확인한 사실을 대화에 남긴 뒤 다시 제안한다.

선택 범위에 메시지를 남긴 사람이라면 누구나 확인할 수 있다.

- **결론과 변경안 승인**: 표시된 결론과 정확한 변경안으로 위키 Draft PR을 만든다.
- **결론 수정**: 사람이 결론을 고치면 새 변경안을 만든다. 수정된 변경안을 다시 확인하고 승인한다.
- **반영하지 않기**: 이 제안을 취소한다.

관리자나 명령 실행자라도 선택 범위의 대화에 참여하지 않았으면 승인할 수 없다. 봇과 webhook 작성자는 승인자로 계산하지 않는다. 제안 후 대화나 대상 위키 문서가 바뀌면 기존 승인을 사용하지 않는다. `/위키-제안`으로 다시 생성한다.

승인한 뒤에는 봇이 같은 내용을 다시 작성하지 않는다. Draft PR에서 팀원이 검토·merge한 뒤 서버 동기화와 재색인을 거쳐 웹·MCP 검색에 반영된다.

## 매일 정리되는 범위

예약 기능을 켜면 한국 시간 자정에 innolive 카테고리의 일반 채널, 브랜딩 채널·포럼의 공개 게시물, 공용 채널과 그 공개 스레드를 확인한다. 보관된 공개 스레드도 확인한다. 이전에 저장한 범위 이후의 메시지만 새로 처리한다. 첫 실행은 최근 자정 이전 24시간을 확인한다.

기술 결정이나 새 사실이 없으면 변경안을 만들지 않는다. 승인을 기다리는 논의는 다음날 같은 변경안으로 반복 게시하지 않는다. 대화가 길면 범위를 나누고 남은 메시지를 다음 실행에서 처리한다. 예약 수집도 사람이 결론과 변경안을 확인해야 Draft PR을 만든다.

private thread, DM, 음성 채널은 이 위키 수집 범위에 포함하지 않는다.
